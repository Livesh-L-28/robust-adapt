# Getting Support for ROBUST-ADAPT (`robust-adapt`)

Thank you for using ROBUST-ADAPT! We are dedicated to providing clear, responsive support for developers and researchers.

---

## 1. Where to Seek Help

| Purpose | Recommended Channel | Response SLA |
| :--- | :--- | :---: |
| **Questions & How-To Discussions** | GitHub Discussions / Community Forum | 24–48 hours |
| **Bug Reports & Verified Defects** | GitHub Issues (using Bug Report template) | 2 business days |
| **Feature Requests & RFCs** | GitHub Issues (using Feature Request template) | Weekly triage |
| **Security Vulnerabilities** | Private email to `security@robust-adapt.internal` | 48 hours |

---

## 2. Before Submitting an Issue

Before creating a new bug report, please check:
1. **Documentation Search:** Check the [API Reference](docs/api/index.md) and [Troubleshooting Guide](docs/troubleshooting/index.md).
2. **Existing Issues:** Search both open and closed GitHub issues to see if your question or problem has already been resolved.
3. **Reproducible Example:** Prepare a minimal, self-contained Python script using synthetic data (e.g., `np.random.randn`) that reproduces the issue.

---

## 3. Filing an Effective Bug Report

When opening a bug report, include:
- **Exact environment information:** Operating system, Python version (`python --version`), and installed packages (`pip list`).
- **Complete traceback:** The full Python exception and stack trace without truncation.
- **Expected vs. Actual behavior:** Clear description of what you expected to happen vs. what actually occurred.
