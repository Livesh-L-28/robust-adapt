    Document Status: Authoritative Baseline (Phase 1 Deliverable)

    1. Traceable Research Evidence Master Log¶

    This register catalogs empirical evidence, primary technical publications, GitHub repository telemetry, and developer community observations gathered during Phase 1.

    Evidence ID Focus Area Evidence Classification Source Title & URL Publication / Update Date Access Date Evidence Excerpt / Core Observation Interpretation & Significance for AdaptiveML Confidence Limitations
    EVD-ALA-001 Streaming ML FACT River Documentation & JMLR Paper (riverml.xyz, JMLR 2021) 2021 (v0.21.0 in 2024) 2026-11-01 River requires single-instance dict input via learn_one(x, y); batch operations require pandas.DataFrame via learn_many. River does not natively support standard 2D NumPy array mini-batches (partial_fit(X, y)). Python loop iteration overhead on large numeric streams is high. High Dicts offer flexibility for variable features, but sacrifice raw BLAS vectorization.
    EVD-ALA-002 Concept Drift OBSERVATION Menelaus & River ADWIN Issue Trackers (mitre/menelaus, river/issues/845) 2022–2024 2026-11-01 ADWIN and DDM trigger frequent false alarms under noisy or bursty streaming data when \(\delta\) is tuned loosely. Existing detectors mistake transient statistical noise for permanent structural concept drift, triggering unnecessary model resets. High Tuning \(\delta\) tightly increases detection lag on true gradual drifts.
    EVD-ALA-003 Continual Learning FACT Avalanche Library (ContinualAI) (avalanche.continualai.org, JMLR 2021) 2021–2024 2026-11-01 Avalanche is tightly coupled to PyTorch; structured around discrete task/class experiences; requires complex Strategy plugins. Avalanche is oriented toward academic deep-learning benchmark replication (Split-MNIST), not lightweight production tabular streams or CPU edge adaptation. High Excellent benchmark coverage, but steep learning curve and heavy dependency footprint.
    EVD-RLA-001 Label Noise FACT Cleanlab Open Source Documentation (cleanlab.ai, JAIR 2021) 2021–2024 2026-11-01 Confident Learning requires out-of-fold predicted probabilities (pred_probs) computed across the full dataset via cross-validation. Cleanlab is an offline batch data-curation framework; it cannot perform in-training robust risk minimization or streaming noise filtering. High Requires training multiple shadow models to generate out-of-sample probabilities.
    EVD-RLA-002 Imbalanced + Noise FACT Learning with Noisy Labels Over Imbalanced Subpopulations (OpenReview / ACL 2023) 2023 2026-11-01 Standard small-loss noise-filtering criteria assume clean samples have small losses; rare minority classes naturally exhibit higher losses. Standard noisy-label cleaners mistakenly discard legitimate minority/tail samples as "label noise", starving minority classes. High Evaluated primarily on synthetic vision benchmarks; tabular streaming validation needed.
    EVD-RLA-003 Imbalanced ML FACT imbalanced-learn Documentation (imbalanced-learn.org) 2023 (v0.12.0) 2026-11-01 SMOTE and synthetic oversampling require global pairwise distance matrices across all samples; assumes 100% clean ground truth. imblearn fails in streaming environments (no global matrix) and creates synthetic corrupted samples if labels contain noise. High Limited strictly to static offline tabular datasets; no PyTorch autograd integration.
    EVD-RAO-001 Low-Memory Opt FACT bitsandbytes Repository & CPU Kernels (github.com/bitsandbytes-foundation/bitsandbytes) 2022–2024 (v0.43+) 2026-11-01 bitsandbytes was originally CUDA-only; recent CPU backends require x86 AVX2/AVX-512; CPU step latency suffers significant quantization penalty. Pure CPU practitioners face severe installation friction, hardware instruction traps, and high dequantization latency on commodity hardware. High CPU backend is improving but remains secondary to GPU CUDA optimizations.
    EVD-RAO-002 Factorized States FACT Adafactor PyTorch Implementation & Paper (Shazeer & Stern, 2018, PyTorch docs) 2018–2024 2026-11-01 Adafactor drops first-moment momentum and uses row/column sums for 2D states; disables foreach multi-tensor loops by default. Substantial memory reduction (\(O(n+m)\)), but suffers from convergence instability, sensitive learning rate warmups, and slower CPU step times without momentum. High Primarily validated on massive Transformer pretraining; less reliable on small/medium architectures.
    EVD-RAO-003 Low-Rank Opt FACT GaLore: Gradient Low-Rank Projection (Zhao et al., NeurIPS 2024) 2024 2026-11-01 GaLore reduces optimizer state memory by 65%–80% via SVD projections; SVD updates trigger CPU memory spikes and compute latency. Periodic SVD on CPU introduces substantial compute pauses; fp16/bf16 SVD exhibits numerical instabilities forcing fp32 fallback. High Restricted to 2D linear weight matrices; requires tuning projection rank and gap.
    EVD-ULC-001 ML Orchestration OBSERVATION Public Technical Architectures & MLOps Toolkits (ZenML, Prefect, Ray Train) 2022–2024 2026-11-01 Existing orchestration tools manage pipeline execution (DAG scheduling, artifact storage, Docker containers), not in-loop algorithmic arbitration. No standard Python library coordinates drift detection, sample reliability weighting, and memory budgeting within the model training loop. High MLOps workflow tools operate at the infrastructure level, leaving algorithmic glue code to users.
    EVD-DX-001 Developer Trust OBSERVATION Python ML Community Discussions (Hacker News, Reddit r/MachineLearning) 2023–2024 2026-11-01 Developers reject libraries requiring complex configurations, non-standard APIs, heavy compiled dependencies, or cloud lock-in. scikit-learn API compatibility (fit, partial_fit, predict) and zero mandatory compiled dependencies are critical for developer adoption. High Qualitative sentiment; corroborated by GitHub issue volume in complex C-extension libraries.

    2. Inferences, Hypotheses, and Strategic Recommendations¶

    2.1 Inferences (Reasoned Interpretations)¶

    • INF-001: The streaming ML market is polarized between lightweight single-event tabular tools (River) and heavy academic deep-learning frameworks (Avalanche). There is an unaddressed gap for a vector-native (2D NumPy ndarray), CPU-first incremental learning toolkit compatible with standard scikit-learn pipelines.
    • INF-002: Data cleaning tools (Cleanlab) and resampling tools (imbalanced-learn) are structurally incapable of handling live streaming data. They require global multi-pass cross-validation and distance matrices, making in-training stream adaptation impossible.
    • INF-003: The optimizer efficiency market is overly focused on multi-GPU LLM training (bitsandbytes, DeepSpeed). Commodity CPU workstations, edge appliances, and developer laptops are underserved by memory-efficient optimizers that do not require specialized CUDA drivers or complex AVX compilation.

    2.2 Working Hypotheses (Requiring Empirical Validation in Phase 12)¶

    • HYP-001: An adaptive learning algorithm operating on 2D NumPy arrays via partial_fit can achieve \(>5\times\) higher throughput than dict-based streaming loops without sacrificing adaptation speed.
    • HYP-002: Integrating a density-aware margin metric into loss-based sample weighting will prevent the accidental deletion of minority-class samples under symmetric and asymmetric label noise.
    • HYP-003: A memory-reduced optimizer state utilizing block-wise dynamic scaling and running on pure NumPy/PyTorch CPU can reduce optimizer memory by \(\ge 30\%\) without the convergence collapse associated with momentum-free Adafactor.
    • HYP-004: An in-loop Unified Learning Controller that arbitrates drift alerts against sample noise scores can suppress \(>50\%\) of false-alarm model resets on dirty data streams.

    2.3 Strategic Product Recommendations¶

    • REC-001: Position AdaptiveML as an Algorithmic Companion: Explicitly complement scikit-learn and PyTorch. Do not build a new runtime, autograd engine, or end-to-end MLOps platform.
    • REC-002: Strictly Preserve Decoupled Pillars: Ensure ALA, RLA, and RAO are 100% functional standalone. Treat ULC as an optional coordinator for advanced pipelines.
    • REC-003: Zero-Compiled-Core Policy: The core runtime must install cleanly via pip install adaptiveml without requiring C/C++ compilers, CMake, or CUDA drivers.
