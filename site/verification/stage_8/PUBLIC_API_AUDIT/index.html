    Public API Audit: AdaptiveML Architecture¶

    Project: AdaptiveML / aml-core (0.1.0.dev0)
    Workspace: C:\projects\AdaptiveML
    Audit Date: 2026-11-06
    Auditor: Principal Python SDK Architect & API Design Specialist
    Artifact Path: PUBLIC_API_AUDIT.md

    1. Executive Summary¶

    This document performs an exhaustive audit of every public class, function, dataclass, and exception currently exported by AdaptiveML across its core modules: 1. ALA (Adaptive Learning Algorithms) 2. RLA (Robust Learning Algorithms) 3. RAO (Resource-Aware Optimization) 4. Minority Intelligence 5. ULC & ULC-v4.1 (Unified Learning Controller) 6. State & Serialization 7. Core & Validation

    3. Discovered API Inconsistencies & Remedies¶

    1. Top-Level Package Namespace Inaccessibility:
    2. Issue: Top-level adaptive_ml/__init__.py does not expose core classes. Users must import from deep submodules (adaptive_ml.ala.classifier.AdaptiveClassifier).
    3. Remedy: Standardize top-level exports in adaptive_ml to expose key classes lazily or directly without adding heavy runtime import overhead.
    4. Optimizer Parameter Naming:
    5. Issue: AdaptiveClassifier uses n_features, but early tests confused it with max_features. LowMemoryAdamW uses lr, while some user code assumed learning_rate.
    6. Remedy: Preserve canonical lr and n_features, add property alias or explicit validation messages.
    7. Configuration Object Diversity:
    8. Issue: TreeConfig and ADWINConfig in core.config are frozen dataclasses, while ULCv41Config is mutable with __post_init__ validation.
    9. Remedy: Create a consistent configuration paradigm: dataclasses with clear parameter validation, serialization via asdict(), and clear defaults.
    10. Exception Hierarchy Completeness:
    11. Issue: adaptive_ml.core.exceptions defines 8 exception classes, but some submodules raised generic ValueError or AttributeError for domain-specific errors.
    12. Remedy: Document the full exception tree and map errors to AdaptiveMLError subclasses.

    4. API Audit Conclusion¶

    AdaptiveML has a remarkably comprehensive and sound underlying algorithm implementation across all four pillars. The primary requirement for Stage 8 is unifying the developer import surface, creating unified top-level SDK access, and providing clear, executable tutorials and documentation.
