    AdaptiveML — RAO Algorithm Specifications: Resource-Aware Optimization¶

    Document Status: Complete Baseline Deliverable (Phase 6)
    Document Identifier: DOC-DES-P6-005
    Last Updated: 2026-11-01
    Pillar: RAO (Resource-Aware Optimization)
    Target Downstream Deliverable: DOC-DES-P7-004 (Public API Specification), DOC-DES-P6-009 (Pseudocode Catalog)

    1. Executive Pillar Architecture¶

    The Resource-Aware Optimization (RAO) pillar provides high-performance, memory-bounded deep learning and machine learning optimization designed specifically for CPU-first execution and edge constraints.

    RAO delivers two core algorithmic engines: 1. LowMemoryAdamW: A block-quantized AdamW optimizer executing symmetric 8-bit dynamic quantization of first and second moments in pure NumPy and PyTorch, achieving up to 74.6% optimizer state memory reduction without custom C++ or CUDA compilation. 2. AdaptiveGradientAccumulator: A memory-governed gradient accumulation controller that dynamically modulates accumulation micro-batches to satisfy strict RAM ceilings while preserving exact mathematical gradient equivalence.

                               RAO OPTIMIZER ARCHITECTURE
                                       │
                    Model Parameters theta in R^p, Gradients g_t
                                       │
                      ┌────────────────┴────────────────┐
                      ▼                                 ▼
         ┌─────────────────────────┐       ┌─────────────────────────┐

    2. Algorithm 1: CPU Block-Quantized AdamW (LowMemoryAdamW)¶

    2.1 Problem Definition & Memory Breakdown¶

    In standard AdamW, for a parameter vector \(\boldsymbol{\theta} \in \mathbb{R}^p\) in single-precision floating point (float32, 4 bytes/element): $\(\text{Parameters: } 4p \text{ bytes}, \quad \text{Gradients: } 4p \text{ bytes}\)$ $\(\text{Momentum } \mathbf{m}_t: 4p \text{ bytes}, \quad \text{Variance } \mathbf{v}_t: 4p \text{ bytes}\)$ $\(\text{Total Optimizer State Memory: } S_{\text{AdamW}} = 8p \text{ bytes}\)$ For a 100M-parameter model, the optimizer states alone consume \(800\text{ MB}\), and for a 1B-parameter model, \(8\text{ GB}\). In memory-constrained environments or multi-process CPU workers, this causes thrashing and out-of-memory (OOM) termination.
    While CUDA libraries (e.g. bitsandbytes) exist, they rely on pre-compiled CUDA kernels and fail on standard CPU environments (x86_64, ARM64) without complex external build tools.

    2.2 Mathematical Formulation of Block Quantization¶

    Let parameter vector \(\boldsymbol{\theta}\), gradient \(\mathbf{g}_t\), first moment \(\mathbf{m}_t\), and second moment \(\mathbf{v}_t\) be indexed by \(i \in \{1, \dots, p\}\).
    We partition the \(p\)-dimensional vectors into contiguous, non-overlapping blocks of size \(B_q\) (default \(B_q = 256\) elements): $\(\mathcal{B}_b = \left\{ (b-1)B_q + 1, \dots, \min(b B_q, p) \right\}, \quad b \in \left\{ 1, \dots, N_b \right\}, \quad N_b = \left\lceil \frac{p}{B_q} \right\rceil\)$

    2.2.1 First-Order Moment Quantization (int8)¶

    Since momentum \(\mathbf{m}_t \in \mathbb{R}^p\) can be positive or negative, we apply symmetric signed 8-bit integer quantization over each block \(\mathcal{B}_b\): 1. Dynamic Block Scale Calculation: $\(s_b^{(m)} = \frac{\max_{i \in \mathcal{B}_b} |m_{t, i}|}{q_{\max}^{(m)}} + \epsilon_{\text{quant}}\)$ where \(q_{\max}^{(m)} = 127\) for signed 8-bit integer (int8), and \(\epsilon_{\text{quant}} = 10^{-12}\). 2. Quantization Mapping: $\(\tilde{m}_{t, i} = \text{clip}\left( \left\lfloor \frac{m_{t, i}}{s_b^{(m)}} \right\rceil, -127, 127 \right) \in \text{int8} \quad \forall i \in \mathcal{B}_b\)$ where \(\lfloor \cdot \rceil\) denotes the round-to-nearest-integer operator. 3. Dequantization: $\(\hat{m}_{t, i} = \tilde{m}_{t, i} \cdot s_b^{(m)}\)$

    2.2.2 Second-Order Moment Quantization (uint8)¶

    Because variance \(\mathbf{v}_t \in \mathbb{R}_{\ge 0}^p\) is strictly non-negative, we utilize unsigned 8-bit integer quantization (uint8), doubling the effective dynamic resolution: 1. Unsigned Dynamic Block Scale: $\(s_b^{(v)} = \frac{\max_{i \in \mathcal{B}_b} v_{t, i}}{q_{\max}^{(v)}} + \epsilon_{\text{quant}}\)$ where \(q_{\max}^{(v)} = 255\) for unsigned 8-bit integer (uint8). 2. Quantization Mapping: $\(\tilde{v}_{t, i} = \text{clip}\left( \left\lfloor \frac{v_{t, i}}{s_b^{(v)}} \right\rceil, 0, 255 \right) \in \text{uint8} \quad \forall i \in \mathcal{B}_b\)$ 3. Dequantization: $\(\hat{v}_{t, i} = \tilde{v}_{t, i} \cdot s_b^{(v)}\)$

    2.3 Exact Memory Footprint Derivation¶

    Component Standard AdamW (float32) LowMemoryAdamW (Block Quantized) Memory Reduction
    First Moment \(\mathbf{m}_t\) \(p \times 4\text{ bytes} = 4p\) \(p \times 1\text{ byte} + \lceil p/256 \rceil \times 4\text{ bytes} \approx 1.0156 p\) 74.6% reduction
    Second Moment \(\mathbf{v}_t\) \(p \times 4\text{ bytes} = 4p\) \(p \times 1\text{ byte} + \lceil p/256 \rceil \times 4\text{ bytes} \approx 1.0156 p\) 74.6% reduction
    Total Persistent State \(\mathbf{8.000 \, p\text{ bytes}}\) \(\mathbf{2.031 \, p\text{ bytes}}\) 74.6% overall reduction

    2.4 Update Equations and Algorithmic Flow¶

    At step \(t\), for each parameter block \(b \in \{1, \dots, N_b\}\): 1. Dequantize in-place into a reusable scratch buffer of size \(B_q\) (float32): $\(\mathbf{m}_{\text{prev}} = \tilde{\mathbf{m}}_{t-1, \mathcal{B}_b} \cdot s_b^{(m)}\)$ $\(\mathbf{v}_{\text{prev}} = \tilde{\mathbf{v}}_{t-1, \mathcal{B}_b} \cdot s_b^{(v)}\)$ 2. Compute standard exponential moving averages: $\(\mathbf{m}_{t, \mathcal{B}_b} = \beta_1 \mathbf{m}_{\text{prev}} + (1 - \beta_1) \mathbf{g}_{t, \mathcal{B}_b}\)$ $\(\mathbf{v}_{t, \mathcal{B}_b} = \beta_2 \mathbf{v}_{\text{prev}} + (1 - \beta_2) \mathbf{g}_{t, \mathcal{B}_b}^2\)$ 3. Bias-corrected updates: $\(\hat{\mathbf{m}} = \frac{\mathbf{m}_{t, \mathcal{B}_b}}{1 - \beta_1^t}, \quad \hat{\mathbf{v}} = \frac{\mathbf{v}_{t, \mathcal{B}_b}}{1 - \beta_2^t}\)$ 4. Parameter descent step with decoupled weight decay: $\(\boldsymbol{\theta}_{t, \mathcal{B}_b} = \boldsymbol{\theta}_{t-1, \mathcal{B}_b} - \eta_t \left( \frac{\hat{\mathbf{m}}}{\sqrt{\hat{\mathbf{v}}} + \epsilon_{\text{adam}}} + \lambda \boldsymbol{\theta}_{t-1, \mathcal{B}_b} \right)\)$ 5. Re-quantize and store: Compute new scales \(s_b^{(m)}, s_b^{(v)}\), update integer states \(\tilde{\mathbf{m}}_{t, \mathcal{B}_b}\) and \(\tilde{\mathbf{v}}_{t, \mathcal{B}_b}\), and overwrite state arrays.

    2.5 Error Analysis & Convergence Guarantee¶

    2.5.1 Quantization Error Bound¶

    For any element \(i \in \mathcal{B}_b\), the quantization error satisfies: $\(|e_i^{(m)}| = |m_{t, i} - \hat{m}_{t, i}| \le \frac{s_b^{(m)}}{2} \le \frac{\max_{j \in \mathcal{B}_b} |m_{t, j}|}{2 \cdot 127}\)$ $\(|e_i^{(v)}| = |v_{t, i} - \hat{v}_{t, i}| \le \frac{s_b^{(v)}}{2} \le \frac{\max_{j \in \mathcal{B}_b} v_{t, j}}{2 \cdot 255}\)$ Because quantization occurs block-wise rather than tensor-wide, outlier gradients in one parameter tensor do not elevate quantization errors in other parameters.

    2.5.2 Theorem: Convergence on \(L\)-Smooth Non-Convex Objectives¶

    Theorem 3 (Convergence of LowMemoryAdamW):
    Let objective function \(f: \mathbb{R}^p \to \mathbb{R}\) be \(L\)-smooth (\(f(\mathbf{y}) \le f(\mathbf{x}) + \langle \nabla f(\mathbf{x}), \mathbf{y}-\mathbf{x} \rangle + \frac{L}{2} \|\mathbf{y}-\mathbf{x}\|_2^2\)) and bounded below (\(f(\boldsymbol{\theta}) \ge f^*\)).
    Under standard bounded gradient assumptions \(\|\mathbf{g}_t\|_\infty \le G_\infty\), the quantization perturbation \(\mathbf{e}_t\) satisfies \(\|\mathbf{e}_t\|_2^2 \le \frac{p \cdot G_\infty^2}{12 \cdot 127^2}\).
    With step size \(\eta_t = \frac{\eta_0}{\sqrt{t}}\), LowMemoryAdamW converges to a stationary point: $\(\min_{1 \le t \le T} \mathbb{E}\left[ \|\nabla f(\boldsymbol{\theta}_t)\|_2^2 \right] \le \mathcal{O}\left( \frac{1}{\sqrt{T}} \right) + \mathcal{O}\left( \frac{G_\infty^2}{q_{\max}^2} \right)\)$ For \(q_{\max} = 127\), the asymptotic bias term is \(\mathcal{O}(10^{-5} G_\infty^2)\), which is negligible compared to stochastic mini-batch gradient variance.

    3. Algorithm 2: Dynamic Gradient Accumulation (AdaptiveGradientAccumulator)¶

    3.1 Problem Definition & Memory Constraints¶

    When training deep models under strict host RAM limits \(M_{\max}\), the optimal batch size \(B_{\text{target}}\) required for training stability may exceed the memory capacity: $\(\text{MemoryUsage}(B_{\text{target}}) > M_{\max}\)$ Directly reducing batch size to \(B_{\text{phys}}\) introduces high gradient variance and degrades convergence.

    3.2 Formal Mathematical Formulation¶

    Let \(B_{\text{phys}}\) be the maximum physical mini-batch size admissible under \(M_{\max}\).
    The target effective batch size is achieved over \(K_{\text{accum}}\) micro-steps: $\(K_{\text{accum}} = \left\lceil \frac{B_{\text{target}}}{B_{\text{phys}}} \right\rceil, \quad B_{\text{eff}} = K_{\text{accum}} \cdot B_{\text{phys}}\)$

    3.2.1 Accumulated Gradient Formulation¶

    For micro-step \(k \in \{1, \dots, K_{\text{accum}}\}\) with micro-batch \(\mathbf{Z}_k = \{(\mathbf{x}_{k, b}, y_{k, b})\}_{b=1}^{B_{\text{phys}}}\): $\(\mathbf{G}_k = \frac{1}{B_{\text{phys}}} \sum_{b=1}^{B_{\text{phys}}} \nabla_{\boldsymbol{\theta}} \ell(\boldsymbol{\theta}; \mathbf{x}_{k, b}, y_{k, b})\)$ The accumulator maintains the in-place running sum: $\(\mathbf{G}_{\text{accum}} \leftarrow \mathbf{G}_{\text{accum}} + \frac{1}{K_{\text{accum}}} \mathbf{G}_k\)$ When \(k = K_{\text{accum}}\): $\(\mathbf{G}_{\text{accum}} = \frac{1}{B_{\text{eff}}} \sum_{k=1}^{K_{\text{accum}}} \sum_{b=1}^{B_{\text{phys}}} \nabla_{\boldsymbol{\theta}} \ell(\boldsymbol{\theta}; \mathbf{x}_{k, b}, y_{k, b}) \equiv \nabla_{\boldsymbol{\theta}} \hat{R}_{B_{\text{eff}}}(\boldsymbol{\theta})\)$ This guarantees exact mathematical equivalence to computing the full batch gradient in a single step.

    3.2.2 Dynamic Memory Adaptation Policy¶

    If host RAM usage \(M_{\text{current}}\) approaches the safety threshold \(\gamma_{\text{safety}} M_{\max}\) (\(\gamma_{\text{safety}} = 0.85\)): 1. Halve physical batch size: \(B_{\text{phys}} \leftarrow \max\left( \lfloor B_{\text{phys}} / 2 \rfloor, 1 \right)\). 2. Double accumulation steps: \(K_{\text{accum}} \leftarrow \lceil B_{\text{target}} / B_{\text{phys}} \rceil\). 3. Preserve \(B_{\text{eff}}\), guaranteeing zero perturbation to optimizer dynamics while immediately freeing working RAM.
